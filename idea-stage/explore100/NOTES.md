## 1. Does RL Really Incentivize Reasoning Capacity in LLMs Beyond the Base Model?（NeurIPS'25 Oral；清华 LeapLab 黄高组）2504.13837
**一句话**：用大 k 的 pass@k 衡量"能力边界"：RLVR 只在小 k 时占优，k 增大后 base 模型反超。RL 解出的题几乎是 base 解出题的子集，RL 输出在 base 下的困惑度低。distillation 则能真正扩展边界。
**原文里有意思的发现**
- **作者自己展示的"base 模型正确 CoT"是错的**（Fig. 20，AIME24 那道 900 居民题）：式子 900 = 1924 − 437 − 2×234 − 3X 解出来 X ≈ 39.7，模型却直接写出正确答案 73。这正是作者要排除的"蒙对"，而且 AIME24 很可能被污染。所以"base 能采到正确推理路径"的证据本身要打折。人工检查也只覆盖了极少量题（AIME 6–7 题）。
- **温度鲁棒性不对称**（Fig. 17）：base 模型在 T>1 时性能崩塌，RL 模型在各个温度下都稳定。RL 不只是锐化了分布，还让模型对温度扰动不敏感，相当于把概率质量集中到了"高温下也稳定的模式"上。
- **把 RL 模型的温度调到与 base 熵相同，也补不回 pass@k 的差距**（Fig. 18）：边界收窄不能简单归因于熵降低。
- KL 正则（0.001）：pass@1 几乎不变，pass@128 明显更低。也就是说，KL 并没有像通常认为的那样"保住多样性"。
- rollout 数 n 从 8 增加到 32，pass@128 有改善。DAPO 的 pass@1 最高，但 pass@256 掉得最厉害（动态采样把"已会题"挤出去了？）。
- 训练过程中 PPL_base(Y_RL) 单调下降：RL 输出逐渐收缩到 base 分布的高概率区域。
- "只有 RL 能解"的少数题（MATH500 中约 5 题），base 采样到 1024 次也全都能解出。
**我的看法**
- pass@k 混淆了"能力"和"猜测"：k 很大时，答案空间小的题（AIME 整数答案）可以靠枚举蒙对。这篇文章的核心结论对数值答案任务的偏差很敏感。更干净的边界指标应当是"过程正确率@k"，或者用答案空间极大的任务（代码 unit test、证明）。
- 温度鲁棒性这个副产物没人深挖：RL 后的模型对采样温度不敏感，意味着 TTS 中"高温探索"对 RL 模型基本无效。这与 TTS 采样策略直接相关。

## 2. When Thinking Fails: The Pitfalls of Reasoning for Instruction-Following（NeurIPS'25 Spotlight；Harvard 等）2505.11423
**一句话**：在 IFEval / ComplexBench 上，CoT 让 15 个模型里的绝大多数指令遵循能力下降（Llama3-8B 从 75.2 掉到 59.0）。机制解释为"约束 attention"被稀释；缓解方法是由分类器决定是否推理。
**原文里有意思的发现**
- **相当一部分"推理伤害"是评测伪影**：
  - 附录 Example 4：最终 haiku 满足了所有约束，但**推理段里出现了逗号**，被判违反了"no comma"约束。也就是说，评测把约束同时施加到了推理文本上，与正文"只评 answer"的说法矛盾。
  - Example 3：要求"逐字重复请求"，而请求原文里就含有逗号，与"不许用逗号"天然冲突。这是 IFEval 自身的约束冲突，推理模型更"老实"地重复了原文，反而被判错。
- 推理擅长的是**覆盖模型默认习惯的约束**，比如不加句末标点、字母 q 出现 6 次；擅长做"清单式检查"。它不擅长的是"别多说话"：推理会**加入"好心"的额外内容**（解释、翻译、强调），从而破坏约束。
- 推理长度与"推理收益"几乎不相关（Pearson ≈ 0）。
- Self-selective（让模型自己判断要不要推理）：**召回高、精度低**，模型倾向于过度使用推理，即模型不知道自己什么时候不该想。
- Self-reflection 在弱模型（1B、1.5B）和复杂指令上反而更差。
- attention 分析只在 1–2B 小模型上做，"约束 attention 下降"在 LOSE 样本的早中层更明显。
**我的看法**
- 它报告的退化里混有"约束的作用范围"问题（推理段是否计入）和数据集自身的冲突约束。拆开之后，真实效应可能小很多。这又是一个"效应里混有评测设计"的例子。
- "模型不知道何时不该想"（召回高、精度低）比主结论更有意思，可以与 AdaptThink、Thinkless 这类自适应思考工作对照：它们学到的"何时想"是否也是高召回、低精度？

## 3. Thoughts Are All Over the Place: On the Underthinking of o1-Like LLMs（NeurIPS'25 Spotlight；腾讯 AI Lab 涂兆鹏组）2501.18585
**一句话**：o1 类模型在答错时频繁切换思路（"Alternatively"）。错误回答比正确回答多用 225% 的 token、多 418% 的切换；超过 70% 的错误回答里含有至少一个"本可以做对"的早期思路。方法是在解码时对切换词加 logit 惩罚（TIP）。
**原文里有意思的发现**
- **判定"思路正确"的 judge 被告知了标准答案**（prompt 里给出了 Correct Answer A），再让它判断这条草稿"能否推到 A"。这是带标签的判定，本身准确率只有约 82%，而且偏向于把与答案相容的思路判为正确。
- **缺少对照组**：只统计了错误回答里"正确但被放弃的思路"，没有统计正确回答里同类思路的出现率。所以"切换导致错误"和"不确定（题难）导致切换"无法区分，因果方向可能相反。
- 更强的 R1 在 MATH500-Hard 和 GPQA 上的 underthinking 分数反而**更高**，在 AIME 上更低。即"更强模型错的时候更啰嗦"，这一点没有被解释。
- TIP 的超参（α=3，β=600）是在 AIME22/23 上 grid search 得到的，再测 AIME24。增益是 QwQ 从 35.2 到 39.8；对 R1 的增益更小。
- 与 Laconic decoding（选最短的回答）叠加有效：错误回答更长是一个跨工作的稳健现象。
**我的看法**
- 结合第 1 篇（RL 只是锐化分布）和第 8 篇 RPDI-EE：切换词是"不确定性的症状"，而不一定是错误的原因。更有价值的问题是：**在第一个"Alternatively"出现时，模型内部状态能否预测这一题最终会错？** 如果能，就是一个零成本的早停或重采样信号（与 R2R 的分叉 token 同源）。

## 4. Right Question is Already Half the Answer: Fully Unsupervised LLM Reasoning Incentivization（EMPO；NeurIPS'25 Spotlight）2504.05812
**一句话**：用"语义熵最小化"作为奖励，即答案所在语义簇的频率（等价于多数投票奖励），对 Qwen2.5 base 做无标签 RL。Math-7B 从 30.7 提升到 48.1，MMLU-Pro 7B 从 32.1 提升到 50.1，与有监督的 GRPO 相当。
**原文里有意思的发现**
- **只在 Qwen2.5 base 上有效**：Llama3 base"一致性太差、无法收敛"，必须从 instruct 模型起步。作者自己的解释是 Qwen2.5 的预训练语料里混入了 Qwen2-Instruct 生成的 QA 对，因此 base 模型天生会按格式作答。
- 增益很可能**大部分来自格式与答案抽取**：base 模型在 MMLU-Pro / GPQA 上 zero-shot 不一定把选项写进 \boxed{}，RL 之后学会了写。文中没有拿 random reward / format-only reward 作对照（同期 "Spurious Rewards" 工作显示，Qwen-Math 用随机奖励也能涨十几个点）。
- "完全无监督"打了折扣：自然推理任务的训练集用 **Llama3.3-70B 的回答长度**筛掉难题；语义聚类用了**一个有监督微调过的 1.5B verifier**。早期用 DeBERTa 聚类时出现频繁的 reward hacking，说明**聚类器的质量就是隐性的监督**。
- 训练中**回答长度不增长，也没有 "aha moment"**，但准确率照样上升。pass@k 在大 k 时被 base 追平（与第 1 篇一致）。
- 双熵阈值：去掉熵过高的样本（防止强化错误共识）和熵过低的样本（防止过度自信）。
**我的看法**
- 这类"自一致性奖励"本质上是把 maj@k 蒸馏进 pass@1。上限是 maj@k，而不是 pass@k；超过 maj@k 的部分基本不可能出现。可以直接检验：EMPO 后的 pass@1 是否始终 ≤ 训练前的 maj@G。
- "Qwen 预训练里混了 instruct 数据，所以 zero-RL 只在 Qwen 上成功"这个解释在多篇论文里反复出现，却没有人做过受控检验（比如在两种预训练语料上对比 zero-RL 的可行性）。

## 5. Wait, Wait, Wait... Why Do Reasoning Models Loop?（ICML'26 Spotlight；UW-Madison / MSR，Papailiopoulos 组）2512.12895
**一句话**：推理模型在低温下普遍陷入循环。根因是"学习误差"：学生没学好老师的分布。机制有两个：
- (a) **风险规避**：正确的推进动作难学，概率被分散到多个不可区分的候选上，于是容易的循环动作（复述、重置）在 greedy 下胜出；
- (b) Transformer 偏向**时间相关的误差**：在重复出现的决策点上，总是偏向同一个选项。
温度只是治标：循环消失了，回答仍比老师长 2.7 倍。
**原文里有意思的发现**
- 蒸馏学生的循环远多于老师：OpenThinker3-1.5B 在 greedy 下有 30% 的回答循环，老师 QwQ-32B 只有 4%；R1-Distill-Qwen-1.5B 为 76%，32B 为 37%。**instruct 版几乎不循环**，同一底座的 reasoning 版大量循环。
- **轻量 RL（Phi-4-reasoning-plus）对循环几乎没有影响**。
- **Phi-4-reasoning 在简单题上循环更多**（唯一的例外）：它已经找到了答案，然后无限重复 "We'll produce answer in plain text"，属于"**解出之后的循环**"。它是用 o3-mini 数据蒸馏的，与其他模型不同。
- **第二高概率的候选在多次访问之间也高度一致**（60%），但 greedy 从来不会选它。所以循环不是单纯的"自我条件化"（看到自己选过就再选），而是学到的条件分布本身就有持续的偏向。
- 训练数据中只要有 **0.1% 的确定性循环轨迹**，模型一旦开始重复，继续重复的概率就会趋近 1（"催化剂"）。预训练语料里少量的重复文本可能就是来源。
- 训练分布中加入"对已访问选项的 margin=0.1 惩罚"，可以完全消除 greedy 循环，相当于训练时的 repetition penalty。
- v3 版勘误：padding 没有 mask，修正后部分结论（reset 高估、催化强度）有变化。
**我的看法**
- "解出之后的循环"与第 8 篇 RPDI-EE 的验证循环、第 15 篇 safety 的"早锁定"是同一类现象：**答案已定，模型却停不下来**。这对 TTS 和效率都是可以直接利用的信号。
- "学生在老师不难的地方犯难"给出了一个可操作的蒸馏改进：用学生的高 loss 位置定位"难动作"，只在这些位置补提示或做 on-policy 纠偏。作者自己也提到了这个方向。

## 6. Base Models Know How to Reason, Thinking Models Learn When（ICML'26；Oxford / MATS，Neel Nanda、Arthur Conmy）2510.07364
**一句话**：
- 先用小字典（5–50）的句子级 SAE，从推理 trace 中无监督地发现"推理机制"的分类（验证、回溯、设子目标……）。
- 再做"构造式 model diffing"：base 模型负责生成；在 base 与 thinking 模型下一 token 不一致的位置，用 thinking 模型的 SAE 选出类别，在 base 中加入对应的 category vector。
- 结果：对 RL 训练的模型（Open-Reasoner-Zero）能恢复约 76% 的差距，对 SFT 蒸馏的模型（R1-Distill）只能恢复约 11%。结论是 **RL 教的是"何时用"，SFT 教的是"新机制"**。
**原文里有意思的发现**
- 只需对 **5–12% 的 token** 做 steering，就能恢复 RL 模型 76% 的增益。
- 随机方向（范数匹配）会让恢复率变成**负值**（−28%）：用错方向比不干预更糟。随机选位置时，小模型崩溃，32B 仍有 28%（大模型对干预位置更鲁棒）。
- **QwQ-32B（先 SFT 再 RL）的表现像 SFT 模型**，而不像 RL 模型：SFT 留下的"机制改变"在后续 RL 中依然起主导作用。
- 蒸馏模型的恢复率随底座规模上升（1.5B 约 0，14B/32B 约 15–20%）：大底座"已经认识"更多老师的机制。
- 句子级小 SAE 在不同种子下非常稳定（93% 的特征可以匹配），与大 SAE 约 30% 的稳定性形成对比。
**我的看法（重要的混淆）**
- "需要 steering 的 5–12% token"本来就是 base 与 thinking 模型不一致的位置，这个稀疏性是定义带来的，不是发现。
- **RL 与 SFT 的差别很可能只是"离 base 的距离"不同**：ORZ 是在 Qwen base 上做 zero-RL，KL 很小；R1-Distill 用 80 万条 SFT 数据训练，分布偏移大。任何"在 base 上修补"的方法，自然更容易恢复离 base 近的模型。没有控制"与 base 的 KL 或不一致率"来比较两种范式。
- 评测时 thinking 模型的预算只有 **2048 token**，R1-Distill 的长 CoT 会被大量截断，影响"差距"的分母。
- 尽管如此，"RL ≈ 学习何时调用已有行为"与第 1、4 篇一致，并给出了一个可操作的接口：如果 RL 的增益能被稀疏 steering 复现，那么**用 steering 近似 RL**（training-free 的推理能力迁移）是一个实际方向。

## 7. Do We Need Adam? Surprisingly Strong and Sparse RL with SGD in LLMs（ICML'26 Spotlight；UIUC Hao Peng 组）2602.07729
**一句话**：在 RLVR 中，纯 SGD（lr=0.1）的效果与 AdamW 相当甚至更好（代码 pass@1 平均 +8.7%），省 15.7GB 显存，而且**只更新了 0.02% 的参数**（AdamW 更新约 10%）。动量在 RL 中多数情况下有害。
**原文里有意思的发现**
- **RL 的梯度方向前后几乎正交**：AdamW 的累积动量与当前梯度的 cos，SFT 中为 0.997，RL 中为 −0.007。RL 每一步的梯度近似"新的随机方向"，所以动量几乎无用。SFT 的 0.997 本身也很惊人：说明 SFT 的梯度方向几乎恒定。
- RL 中 Adam 二阶矩 √v 的标准差比 SFT 小 22 倍，参数间的尺度很均匀，自适应学习率没什么可适应的。
- **AdamW 的有效学习率**：名义 lr 为 1e-6，但由于梯度极小（√v 约 1e-7），有效步长集中在 1 到 10 之间。也就是说，RL 里的 AdamW 本质上是一个**每个参数都按固定幅度移动的 sign-SGD**，这正是它"更新稠密"的原因。
- SGD 对学习率很宽容：0.1 和 1 都能收敛，到 10 才崩；1e-2 偏小。
- PPO 的 critic 用 SGD 时也只更新了 8% 的参数（AdamW 为 61%）。
**我的看法**
- **"0.02% 稀疏更新"多半是数值精度的产物**：稀疏度用 bf16 下阈值 1e-5 来判定。SGD 的更新正比于梯度大小，大多数参数的累计变化低于 bf16 的分辨率，被舍入掉了；AdamW 则把每个参数都推动约 1e-6 量级。所以"RL 只需要改 0.02% 的参数"更准确的表述是"RL 梯度能量集中在极少数坐标上"。文中**没有分析是哪些参数**（哪些层、哪些 head、是否与特定 token 或 embedding 行相关）。这是一个很便宜、可能有发现的追问。
- 如果 RL 的有效更新确实集中在约 0.02% 的坐标上，那么 **"RL 增量"可以极致压缩**（只存稀疏 delta），可以用来做 RL 能力的跨模型迁移或合并，与第 6 篇"RL 只是稀疏地调用已有机制"相互印证。

## 8. On the Interplay of Pre-Training, Mid-Training, and RL on Reasoning LMs（ICML'26 Spotlight；CMU Graham Neubig / Xiang Yue）2512.07783
**一句话**：在 GSM-Infinite 式的合成 DAG 算术任务上，从零训练 100M 模型，分别控制预训练、mid-training 和 RL 的数据分布。结论：
- RL 只有在两种条件下才能带来真正的能力增长（pass@128 提升）：预训练留有余地，且 RL 数据处于"能力边缘"（pass@1≈0 但 pass@k>0）；
- 迁移到新语境需要预训练中**至少约 1%** 的原子技能曝光；
- 同等算力下，mid-training 加 RL 优于纯 RL；
- 过程奖励能减少 hacking。
**原文里有意思的发现**
- **曝光阈值很陡**：长尾语境 B 在预训练中占 0% 或 0.1% 时，RL 完全无法迁移；占 1% 时，可以一路泛化到最难的 op=20。存在类似"种子"的临界比例。
- 如果预训练中 B 与 A 共享推理原语（0.1% 的 B，但覆盖 op 2–20），那么 RL 阶段**0% 的 B 也能大幅迁移**。迁移靠的是"结构共享"而不是"见过多少"。
- 难题上，RL 后正确解的计算图与语境 A 的拓扑相似度**降低**：模型在生成"新结构"，而不只是复制。这是"RL 能创造"的一个可量化证据，尽管只出现在合成任务上。
- 算力分配：OOD-edge 上，"重 mid-training + 轻 RL"的 pass@1 最好；OOD-hard 上，"重 RL"最好。也就是说，**mid-training 负责可靠性，RL 负责外推**。
- 过程验证奖励（只有过程正确才给结果奖励）让外推任务的 pass@1 提高 4–5%，结构性错误减少。
**我的看法**
- 这里的"外推"是深度（op 数）外推，本质上接近长度泛化。RL 能外推，可能是因为 RL 的 rollout 本身就比 SFT 数据更长、覆盖了更大的 op 区间（op 11–14 的训练数据是 RL 时才首次见到的）。这与"RL 本身的学习机制"之间缺少拆分。
- "1% 阈值"值得在真实 LLM 上检验，例如新语言、新领域在预训练中的占比与 RL 迁移性之间的关系。这个问题具有实际的数据配比价值。

## 9. RAGEN-2: Reasoning Collapse in Agentic RL（ICML'26 Spotlight；Northwestern Manling Li 组 / Stanford 李飞飞、Yejin Choi）2604.06268
**一句话**：多轮 agent RL 中会出现 **"模板坍缩"**：推理在同一输入内看起来多样（熵不低），但对不同输入几乎一样（与输入的互信息 I(X;Z) 很低）。
- 作者用"batch 内交叉打分"作为 MI 的代理：把每条推理放到所有 prompt 下算似然，看能否认回它自己的 prompt。
- 机制：组内奖励方差小 → task 梯度小，而 KL / 熵正则的梯度与输入无关、大小恒定 → 正则主导更新，抹平了输入差异。
- 方法：按组内奖励方差做 top-p 过滤 prompt。
**原文里有意思的发现**
- **MI 的下降早于任务成功率的下降**，可以作为提前预警。熵与最终性能的 Spearman 是 **负的**（−0.11 到 −0.14），MI 是正的（+0.39）。即"熵稳定"这个常用的健康指标方向都错了。
- 在 8 个环境中，**agent RL 后推理长度单调下降**（"推理压缩"），与数学 RL 中长度增长的现象正好相反。
- 格式正确率接近 100% 时 MI 仍然可以很低：格式与"是否针对输入"无关。
- 按 RV 四分位分别训练：只用最高方差的 1/4 prompt 训练最好，单调递减。环境随机性超过 80% 时过滤失效（RV 不再反映信号）。
- 简单的预判指标 Std(RV)/Mean(RV)：比值小（RV 分布单峰）时过滤反而有害（FrozenLake 上 −5%）。
- 只做 prompt 级过滤（保留高方差的 prompt）优于 trajectory 级过滤（在每个 prompt 内只留最好和最差的样本）。
**我的看法**
- MI 代理的 batch 只有 P=8 个 prompt，随机水平为 1/8，估计的方差会很大。用模型自己的似然做"认回"，也可能把"推理里复述了输入"当成高 MI。
- "正则梯度与输入无关，在低信号时主导更新"这个视角可以推广到数学 RL 中 KL/熵正则的副作用，以及 MLLM 的 RL 里**视觉条件依赖下降**（推理对图像的 MI 降低，即"不看图"）。用同样的交叉打分（对图像而不是对文本 prompt），就能直接度量 MLLM RL 是否"越训越不看图"。这是一个便宜又新的诊断。

- 先用 Puzzle NAS 删掉一批注意力层，会留下几十个连续的"只剩 FFN"的块。

**我的看法**
- "删掉注意力后剩下的 FFN 链是近恒等、可交换的"与 LinearPatch、层冗余、ShortGPT 一系列结果一致。但这里多了一个更强的结论：**深层 FFN 的顺序本身几乎不重要**。这意味着在这些区域，"深度"更像"宽度"。

**我的看法**
- 这是工程型论文，但有两个可复用的观察：
  - 低秩压缩中的"**范数不平衡会让联合 PCA 偏向某一方**"。在任何"多源联合低秩"场景都适用，例如跨层 KV 共享、视觉与文本 token 的联合压缩。

**一句话**：
- 在 Blackwell 的 FP4 Tensor Core 上实现 NVFP4 microscaling（1×16 分组）注意力，RTX5090 上达到 1038 TOPS，是 FlashAttention2 的 5 倍。

- 原本就答对的输入里，**71.9% 存在更短的正确程序**；原本答错的输入里，34% 能被一个层数更少的程序纠正。
- **"循环"比"跳过"更有用**，两者结合最好。越难的题越需要非标准程序。
- 有效程序有强烈的局部性偏好：57.7% 的模块只含 1 层，绝大多数只重复一次，长程跳转不到 3%。
- 准确率随总执行深度单调上升，形成"latent 层面的 test-time scaling"。
**我的看法（存疑之处）**
- MCTS 找"有效程序"时用的是**答案正确性作为奖励**，本质是 pass@k 式的 oracle 搜索。"34% 的错误能被纠正"与"随机扰动权重或激活后采样 k 次也能碰对"之间并没有对照。缺少的基线是**随机层扰动加正确性筛选**。
- 不过有一点是真正有信息量的：循环中间层比跳层更有用，且只需循环一次。这与 FFN Fusion（第 21 篇，中后段 FFN 近似恒等且可交换）一起说明，**中间层更像在做迭代精化，而不是不可替换的流水线步骤**。

## 28. How Much Is One Recurrence Worth? Iso-Depth Scaling Laws for Looped Language Models（ICML'26；TUM / Imperial / MCML）2604.21106
**一句话**：
- 固定有效深度为 20 层（prelude 2 层 + 共享块循环 r 次 + coda 2 层），对 r ∈ {1,2,4,8} 训练 116 个模型，覆盖约 50× 的计算范围。
- 拟合联合 scaling law L = E + A(N_once + r^φ N_rec)^-α + B D^-β，得到"循环等价指数" **φ = 0.46**：循环一次大约相当于半个独立块。
**原文里有意思的发现**
- 例子：r=4 时，410M 的循环模型效果与 580M 的非循环模型相当，但训练成本相当于 1B 的非循环模型。在等计算量下，**循环模型的 loss 前沿始终落后**，且差距随 r 增大。

- Hyperconnections 把 φ 提高到 0.65，r=2 在部分预算下甚至能打平或超过 r=1。
- **下游推理任务上没有看到"循环模型更擅长推理"的信号**，在 20× 外推的规模下也没有。只有参数化知识类任务与验证 loss 同步变化。
**我的看法**
- 这篇给流行叙事"looped / latent reasoning 带来推理优势"泼了冷水：在小规模下，同等计算的循环既不如独立层，也看不到推理收益。
- 方法论上，"用一个指数把机制收益和训练侧收益分开"可以推广。例如对 MoE 的专家共享、KV 共享，或对"CoT 长度 vs 参数"（每个 CoT token 值多少参数）都可以定义类似的 φ。

## 31. Predictable Scale Part II, Farseer: A Refined Scaling Law in LLMs（NeurIPS'25 Spotlight；StepFun 等）2506.10972

## 32. EvoLM: In Search of Lost Language Model Training Dynamics（NeurIPS'25 Oral；Harvard / Stanford / EPFL / CMU）2506.16029
**一句话**：
- 从零训练 100 多个 1B 和 4B 模型，每个都跑完整的学习率调度，覆盖预训练 → 领域持续预训练（CPT）→ SFT → RL（PPO）的完整生命周期。

**我的看法**
- "中间 checkpoint 不可靠"直接动摇了大量用 OLMo、Pythia 中间 checkpoint 研究"能力何时出现"的分析论文的结论。
- "预训练越久越难后训练"与 "Overtrained LMs are harder to fine-tune"（ICML'25）一致，可能与第 13 篇（内在维度）有关：过训练降低了可塑性。

## 33. The Emergence of Sparse Attention: Impact of Data Distribution and Benefits of Repetition（NeurIPS'25；ETH / Google）2505.17863
**一句话**：
- 用一个"必须只关注一个 token 的线性回归"玩具任务，解析推导出 sparse attention 的涌现机制：
  - 注意力初始是均匀的，FFN 先慢慢对齐目标，注意力随后才获得信号。
  - 两者形成正反馈后，loss 突然下降。
- 平台期长度服从幂律 T_plateau ∝ √d·T。
- **重复可以显著加速涌现**，结论在 induction head（associative recall）任务上也成立。
**原文里有意思的发现**
- **FFN 先学，注意力后学**：线性化动力学显示 W 必须先与 W* 对齐，注意力分数才有梯度。这与"注意力模式决定涌现"的直觉顺序相反。
- **上下文内重复**（相关 token 在上下文中出现 B 次）等价于把序列长度缩短为 T/B。**跨样本重复**（某个特定 token 被过度表示）**即使在没有重复的测试数据上也能加速**：在重复方向上学得快会更早抬高注意力，进而带动其他方向。
- 但跨样本重复"不是免费午餐"：长期看会变慢，在真实 Transformer 中还会过拟合。重复过多时会先过拟合，之后出现类似 grokking 的迟到泛化。
- Induction head 的涌现时间对上下文中的 pair 数量呈 **2.25 次幂**，对词表大小只有 0.79 次幂。作者假设是两个稀疏注意力层的耦合把指数叠加了起来。
- Adam 换成 SGD 会大幅推迟涌现。
**我的看法**
- 对长上下文训练的启示："**涌现时间对序列长度呈超线性**"说明在长上下文中学会新的检索能力代价极高，或许可以解释为什么长上下文能力往往需要专门的数据（例如人为在上下文中重复关键信息）。
- "FFN 先于注意力"可以在真实 LLM 的预训练 checkpoint 上检验，也可以用来解释 MoBA（第 23 篇）中稀疏注意力在 SFT 阶段梯度不足的问题。

## 36. How much do language models memorize?（NeurIPS'25 Oral？；FAIR / DeepMind / Cornell / NVIDIA）2505.24832
**一句话**：
- 用"压缩"定义样本级记忆：非预期记忆 = H(x|参考模型) − H(x|参考模型, 目标模型)，用似然近似。这样可以把它与泛化分开。
- 在均匀随机比特串上训练，测得 **GPT 类模型的容量约为 3.6 bits/参数**。
**原文里有意思的发现**
- **精度翻倍，容量几乎不变**：bf16 → fp32 只把容量从 3.51 提高到 3.83 bits/参数，多出来的 16 bit 几乎都没用于存储。这与"模型能量化到 2 到 4 bit 而能力不掉"一致。
- 在真实文本上，模型**先记忆，记满容量后才开始泛化**；非预期记忆在数据量超过容量后反而下降。
- **双下降恰好发生在"数据信息量 ≈ 模型容量"的位置**，给双下降一个可计算的解释：存不下单个样本时，模型被迫在样本间共享信息。
- 数据集足够大且严格去重时，**训练集的可抽取率收敛到测试集的可抽取率**。也就是说，"能抽取出来"完全来自泛化，而不是记忆。
- 超过容量后，**被记住的是含罕见 token 的样本**（TF-IDF 越高记忆越多）。记忆最多的是一段日语或其他非英语序列，说明记忆集中在长尾上。
- **成员推断比抽取容易得多**：有时抽取率为 0，成员推断 F1 却高达 0.97。按 scaling law 推算，现代 LLM 的训练数据太多，**对平均样本做成员推断几乎不可能**。
**我的看法**
- "约 3.6 bits/参数"给 KV 压缩、量化、低秩等压缩方法提供了一个信息论上的参照：若 bf16 中真正有用的只有约 3.6 bit，那么 4-bit 量化的损失主要来自**分布错配**，而不是容量不足。
- "严格去重时抽取率 = 测试抽取率"会动摇很多版权/记忆论文的结论：它们用的语料没有严格去重。

## 37. Alignment Pretraining: AI Discourse Causes Self-Fulfilling (Mis)alignment（ICML'26；Geodesic / Cambridge / Oxford / UK AISI）2601.10160
**一句话**：
- 从零预训练多个 6.9B 模型（500B token 预训练 + 50B token midtraining），**只改变"关于 AI 的论述"**。四个版本：

  - 加入约 1% 的"AI 在高风险情境下做对的事"合成文档。

## 38. Efficient Numeracy in Language Models through Single-token Number Encodings（ICML'26；TUM / Imperial）2510.06824
**一句话**：
- 先测 8 个前沿 LLM 在 9 类数值任务上的表现，发现**乘除法、指数、标准差必须靠长推理链才能做对，一次计算要 5K 到 30K 个推理 token**。
- 提出 BitTokens：每个数用一个 [NUM] token 表示，embedding 中加入该数 IEEE-754 float64 的 64 个比特及其倒数的比特，输出端用 sigmoid 头逐比特预测。
- 小模型由此就能近乎完美地学会四则运算。
**原文里有意思的发现**
- 前沿模型在比较、排序、最值、区间判断上几乎满分，加法和求均值也很好。**但所有非推理模型在乘法、除法上的 log-sMAPE 都低于 60%**，推理模型在这些任务上动辄消耗上万 token。
- 理论上证明了**正弦（Fourier）数字编码 FoNE 的根本缺陷**：在正弦编码下加法是逐元素相乘（局部、无需进位），但乘法是非局部的，必须先解码、再计算、再编码。改用对数空间后乘法变简单，加法又变难。作者尝试用 MoE 同时编码两种空间，没有成功。
- IEEE-754 天然把数分成"对数的指数部分"和"线性的尾数部分"：乘法 = 指数相加 + 尾数相乘 + 符号位 XOR，加法 = 按指数对齐后加尾数。**硬件上已解决的表示问题可以直接借用。**
- 逐比特 BCE 损失并不连续（8 = 1000 和 3 = 0011 对 7 = 0111 的损失与数值距离不一致），但模型能学会处理这种不连续。
**我的看法**
- "表示决定可学习的算法"是一个很干净的观点，与第 35 篇（tokenizer 决定鲁棒性，规模救不了）相呼应。
- 对推理效率很有意义：数学类 CoT 的 token 有相当一部分花在逐位算术上。可以统计 R1 类模型 AIME 推理中算术 token 的占比，估计"如果数值表示合理，能省多少 CoT"。

## 39. The Flexibility Trap: Rethinking the Value of Arbitrary Order in Diffusion Language Models（ICML'26；清华 LeapLab / 阿里）2601.15165
**一句话**：
- 理论上，扩散 LLM 的任意顺序生成是自回归（AR）顺序的超集，但在数学和代码上**任意顺序的 Pass@k 曲线更平**，可解题集合基本是 AR 顺序可解题集合的子集。
- 原因是模型利用顺序自由度绕开了高熵的"分叉 token"。
- 因此 RL 时直接把 dLLM 当 AR policy、用标准 GRPO 训练（JustGRPO）即可，GSM8K 达到 89.1%，推理时仍可并行解码。
**原文里有意思的发现**
- 在 LLaDA 上用 Pass@1024 统计 HumanEval，**21.3% 的题只有 AR 顺序能解，只有任意顺序能解的仅 0.6%**。
- 半自回归的块大小 B 从 1 增大到 32，**Pass@k 单调下降**：越自由，潜力越小。
- 被推迟解码最多的 token 正是 "Therefore / Thus / Since" 这类逻辑连接词。
- **"熵退化"**：全局平均熵相同，但分叉 token 在任意顺序下解码时熵大幅降低。原因是模型先写出容易的"未来"内容，再回填连接词，此时连接词已被上下文决定，不再是一个开放的分支选择，而是"事后对齐"。
- 任意顺序在 k=1 时往往更好，即单次生成更连贯，但探索性更差。
- 用 JustGRPO 训练后，**并行解码的 token 越多，相对原模型的增益越大**。
**我的看法**
- 这是本次阅读中"分叉 token"主题最漂亮的一个例证：**可探索性 = 在分叉点保持熵**。它把第 1 篇（RL 锐化）、第 10 篇（量化损伤集中在分叉 token）、第 20 篇（数值噪声集中在分叉 token）串了起来。
- 反过来可以设计：AR 模型的推测解码、并行或树搜索在分叉点做决策时，也会因"先看到未来"而熵退化吗？例如 Multiverse（第 29 篇）在 Map 阶段先写 outline，再生成各分支，也可能出现同样的过早收敛。
- 对 MLLM 的启示：视觉 token 剪枝、提前给出答案摘要等"先确定容易部分"的做法，可能都会降低探索多样性。

## 40. WeDLM: Reconciling Diffusion Language Models with Standard Causal Attention for Fast Inference（腾讯微信 AI 技术报告；Tencent / 北大 / 清华）2512.22737
**一句话**：

**我的看法**
- 与第 39 篇形成很好的对照：**扩散 LLM 在质量（探索）和速度（缓存）两个维度上都被"拉回左到右"**。任意顺序这一理论卖点在实践中两头都不占优。

- 与第 41 篇合起来看：**VLM 的视觉推理本质上是"把图转成文字后在文字空间推理"**。凡是不能被语言化的视觉操作（轮廓追踪、整体比较），都会失败。

## 45. Dissecting Multimodal In-Context Learning: Modality Asymmetries and Circuit Dynamics in Transformers（ICML'26；TUM / Helmholtz / DeepMind）2601.20796
**一句话**：
- 用 GMM 合成的"两模态 + 共享标签"分类任务，训练含 RoPE、RMSNorm、SiLU 的两层小 Transformer，研究多模态 ICL 何时出现，以及背后的电路。

**原文里有意思的发现**
- **RoPE 抑制 ICL**：与绝对位置编码相比，RoPE 下 previous-token head 和 induction head 更难形成，需要更高的数据复杂度才能出现 ICL。作者认为旋转式位置编码缺少"固定偏移"的离散线索。
- **单模态时，模型越大越倾向记忆（IWL）而不是 ICL**。加 head 比加层更推向记忆，因为更多的 head 提供了更多独立的记忆槽位。
- **多模态存在不对称**：主模态（M1）用高多样性数据预训练后，次模态只需要很低的类别多样性（K2=256，对比 K1=8192）就能出现多模态 ICL。即**主模态安装了 ICL 电路，次模态只需要被映射进来**。
- 与单模态相反，**多模态下规模越大 ICL 越好**：新增容量被用于"把次模态接入已有电路"，而不是用于记忆。
- **不用预训练、从头联合训练时，不对称会反转**：模型锚定在次模态上，因为它在位置上与标签相邻。
- 次模态的类内变化（ε2）对 ICL 的帮助远大于主模态的类内变化。两模态的 Zipf 偏斜一致（α≈1）时最好。
- 编码器质量（验证集准确率）强烈预测多模态 ICL；投影维度越高，跨模态对齐（CKA）越差。
**我的看法**
- "次模态只需接入主模态电路"在机制上解释了为什么 MLLM 的视觉推理本质上是"语言化后再推理"（第 41 到 43 篇）：**推理电路属于语言模态**，视觉只是被投影进来的输入。这也说明了为什么"不可语言化"的视觉操作会失败。
- "RoPE 抑制 induction"与第 39 篇（扩散 LLM 更依赖左到右）、TransMLA（第 22 篇，RoPE 位置信息可集中到少数维度）可以联系起来：位置编码的设计可能在悄悄影响 ICL 和推理。

## 47. Vision Transformers Don't Need Trained Registers（NeurIPS'25 Spotlight；UC Berkeley）2506.08010
**一句话**：
- ViT 中的高范数离群 patch（注意力 sink）是由**极少数 MLP 神经元（register neurons）**写入的：OpenCLIP 第 6 层约 5 个神经元，LLaVA 的 CLIP 编码器中约 100 个（总数约 10 万）。
- 把这些神经元在所有 patch 上的最大激活复制到一个额外的零初始化 token 上、其他位置置零，就能在测试时"装上"一个寄存器，不需要重训。
- 结果：注意力图干净了；在 DINOv2 上，无监督物体发现提升约 21 corloc，零样本分割提升约 5 mIoU，基本追平用寄存器重训的模型。
**原文里有意思的发现**
- 离群值**必须存在于某个 token 中**：直接把 register neurons 置零，OpenCLIP 零样本 ImageNet 准确率从 70.4% 掉到 55.6%（随机置零 10 个神经元只掉约 1 个点）。sink 是计算所必需的"空操作"出口。
- 激活复制到哪个 patch，离群值就出现在哪里，**甚至可以摆成心形**。
- 理论模型：register neuron 的输入/输出方向都落在任务头的零空间中，因此其所在 token 成为 sink，使注意力在该位置变成 no-op，等价于一个显式的注意力偏置（k′, v′）。实验中直接用测试时寄存器的平均 k、v 作为常数偏置，也能保持准确率并去掉伪影。
- **在 LLaVA 中，视觉编码器的离群 patch 会"泄漏"到 LLM 对视觉 token 的注意力中**，产生伪影。加入测试时寄存器后，文本到图像的归因更干净，benchmark 准确率不变。注意：寄存器 token 本身没有送入 LLM。
**我的看法**
- 与第 14 篇（Tell-Tale Norm，高范数 token）、TransMLA（第 22 篇，离群维度）、第 33 篇（sink 是涌现的产物）一起构成"**离群值 / sink 是功能性的**"这一主题：不能删，只能移动。
- 对 MLLM 视觉 token 剪枝的直接启示：**按注意力打分的剪枝会保留这些高范数 sink patch**，而它们不携带局部信息。如果先用测试时寄存器把 sink 移出图像，基于注意力的剪枝分数会更准确。这一点可以快速验证，需要查新（已有 VisionZip 等利用"主导 token"的做法，但"先移 sink 再剪枝"可能还没人做）。

**我的看法**

## 57. Equivalence of Context and Parameter Updates in Modern Transformer Blocks（ICML'26；Cambridge / Google Research）2511.17864
**一句话**：
- 把"上下文的作用等价于对 MLP 权重做一个秩 1 补丁"（Dherin et al. 2025，原先只适用于带 bias 的 vanilla block）推广到现代架构：Gemma（前后 RMSNorm 加门控）、Llama、Falcon、MoE、并行 block。
- 提出"输入可控 + 输出可控"的统一判据。实验中，在 Gemma3 1B/4B（含图像上下文）和 Falcon 7B 上，**不给上下文、只用补丁后的权重**，就能逐 token 复现有上下文时的输出分布（float32 完全一致）。
**原文里有意思的发现**
- 在 Gemma 上需要对 W_gate、W_up 做秩 1 补丁，并对 post-RMSNorm 的缩放向量 m 做逐元素补丁。后者要除以 MLP 输出的逐元素值，可能接近 0，**在 bf16 下只有 87.5% 的 token 一致**，改用数值稳定的 RMSNorm 反演方案后提升到 100%。
- **反例**：如果 post-RMSNorm 没有可训练的缩放向量，输出被约束在 L2 球面上，"输出可控"就会失败，补丁不存在。
- 这些补丁依赖于具体 token，每一步都要重算。它们只说明了"上下文可以被编译进权重"，**并不说明 Transformer 真的在执行这种学习算法**（作者在文中也明确这样说）。
**我的看法**
- 从数学上讲这是"重写恒等式"：任何残差扰动都能被吸收进足够灵活的参数。真正有意思的是后续的"可复用 thought patch"，即把多个 token 的补丁聚合成一个与 token 无关的补丁，相当于"把 prompt 蒸馏成 LoRA"（另一篇工作）。
- 对我们的潜在用处：如果视觉 token 的作用也可以被秩 1 补丁吸收（文中图像实验已经成功），那么"**把图像编译进权重，再完全丢弃视觉 token**"理论上可行，可以作为极限压缩的理论上界。但实际上每个 token 都要重算补丁，并没有省计算。

- 各模型差异很大，方向相反的效应在汇总后互相抵消：
  - Qwen3-32B 意识到被测后安全回答 +16.5pp。
  - GLM-5 反而更不安全。
  - GPT-OSS-120b 是唯一一个意识到被测后更不对齐的模型（−17pp）。
- 只有 18% 的安全题会同时出现"有意识"和"无意识"两种 rollout，样本量受到限制。
**我的看法**
- 对第 11 篇（Hawthorne 效应：注入"被测试"感知能改变行为）是一个重要的反面证据，并且方法更扎实：有对照注入、有删除实验、有 on-policy 对比。两者合起来看：**说出 VEA ≠ 据此改变行为**，CoT 中的元认知语句多半是装饰性的。这与第 43 篇（"wait, let me look" 只是语言模式）是同一类现象，**CoT 里的"反思/元认知"语句在因果上很弱**。
- 一个可以统一检验的问题："CoT 中哪些句子在因果上重要？"可以用注入/删除加重采样的方法系统扫描各类句子（反思、验证、自我评估），这与 thought anchors 一类工作相关。

## 60. Do LLMs Signal When They're Right? Evidence from Neuron Agreement（ICLR'26 投稿 / 复旦 / 哈工大）2510.26277
**一句话**：
- 对每条采样轨迹，统计"贡献分数（经 unembedding 投影）超过阈值的 FFN 神经元集合"。
- 发现：**正确回答激活的独立神经元明显更少**；**正确回答之间的神经元集合更相似（Jaccard 更高），错误回答分布在簇的边缘**。

**原文里有意思的发现**
- 激活神经元的数量与熵正相关、与 self-certainty 负相关，但 t-SNE 中的簇与熵无关。因此**熵等标量只是高维内部状态的低维投影**。
- 按 token 位置对齐后，正确链在每一步激活的神经元都更少，**不是长度效应**；错误链会反复切换策略，激活的神经元越来越多（与第 3 篇 underthinking、第 50 篇"失败轨迹更迂回"一致）。

- 在代码任务上，"最少激活"的优势会消失甚至反转：代码需要调用更广的知识。
**我的看法**
- "**正确 = 更稀疏 + 更一致**"与第 50 篇（成功轨迹紧凑）、第 9 篇（RAGEN 中的 MI）、第 14 篇（高范数 token）可以统一为一句话：**正确推理在表征空间中是低熵、收敛的，错误推理是发散的**。
- 一个值得做的 training-free 检验：在 MLLM 中用同样的"激活神经元集合一致性"选择答案，或者用它检测幻觉（结合第 50 篇的"幻觉 = 固着"，幻觉可能表现为"稀疏但与其他样本不一致"）。
- 存疑：阈值和"贡献分数"的定义是从同组作者此前的工作中继承来的，缺少随机方向或随机神经元的对照。

## 61. Debate or Vote: Which Yields Better Decisions in Multi-Agent Large Language Models?（NeurIPS'25 Spotlight；UW-Madison）2508.17536
**一句话**：
- 把多智能体辩论（MAD）拆成"多个 agent 投票"和"轮间辩论"两部分。在 7 个 benchmark 上的结论是：**几乎所有收益都来自多数投票，辩论本身几乎不增益**。
- 理论上，把每个 agent 建模为 Dirichlet-Multinomial，辩论中观察同伴答案就是一次贝叶斯计数更新，由此证明 **agent 对正确答案的信念是一个鞅**：期望不随辩论轮数变化（类似 Pólya 罐模型）。
**原文里有意思的发现**
- 实测每轮的平均 agent 准确率几乎是平的，与鞅的预测一致。
- 改进方向是"打破鞅"：
  - **oracle 版**：某个 agent 一旦答对就锁定，不再更新。准确率大涨，例如 Formal Logic 从 0.50 升到 0.68。
  - **可实现版**：与上一轮多数答案一致时就保持不变（Conformist），或以 30% 概率采用多数答案（Follower）。两者都稳定优于原始 MAD。
- 在 32B 模型、异构人格 agent、摘要任务上结论都不变。唯一的例外是医学题上异构人格有一些增益。
**我的看法**
- 与第 53 篇（跨模型同质化）合起来看：如果 agent 之间本来就高度相似，辩论更像是"相互强化已有偏好"。**辩论 = 鞅，投票 = 放大边际优势**。
- 一个更有意思的扩展：辩论中改变答案往往发生在"分叉点"附近。如果只让 agent 在**自身熵高、不确定**时才接受同伴影响（"熵门控更新"），就天然偏向修正而不是被带偏，这是一种 training-free 的打破鞅的方法。值得检验并查新。

**原文里有意思的发现**
- **对延迟的容忍度出乎意料地高**：66% 的系统允许分钟级甚至更长的响应时间，17% 没有设定延迟上限。原因是 agent 主要做后台自动化，比人工快 10 倍就够了。这与系统研究"压低延迟"的主流目标相反。
- 20 个案例中有 17 个使用闭源前沿模型。**不做 RL/SFT 的原因是对模型升级很脆弱**：每次模型版本更新都要重训。甚至**换成更新、更强的模型也可能弄坏现有工作流**，于是不得不同时运行旧模型。
- 85% 的案例自研 agent，而不使用 LangChain、CrewAI 等框架；有团队专门从框架迁回自研。
- 75% 的团队没有正式 benchmark，依靠 A/B 测试和用户反馈。使用 LLM-as-judge 的团队全部会搭配人工复核（低置信度交给专家，高置信度随机抽检）。
- 只有 9% 使用 DSPy 等自动 prompt 优化。
- 只有一个案例（科学发现场景）用了 RL 训练的模型。
**我的看法**
- 很好的"现实校准"：研究界热衷的长链自主、agent RL、多 agent 辩论，在生产中几乎都不用。生产中真正的需求是：**对模型升级稳健的后训练**、运行时的正确性监控与失败检测、样本高效的方法。
- "延迟不敏感"意味着推理时扩展（多采样 + 验证）在生产中是可行的。结合第 60 篇（早期神经元一致性选择）、第 50 篇（推理轨迹几何预测失败），**运行时的"失败预警"信号**有直接的生产价值。

## 64. ECHO: Terminal Agents Learn World Models for Free（Microsoft Research AI Frontiers，2026）2605.24517
**一句话**：
- 在多轮 agent RL（GRPO）中，**终端返回的输出 token**（stdout、报错、文件内容）本来就在 rollout 里，也参与前向，但从不计入损失。
- ECHO 只在这些环境 token 上加一个交叉熵辅助损失（λ=0.05），共用同一次前向，不需要额外 rollout。
- 结果：TerminalBench-2.0 的 pass@1 几乎翻倍（8B 从 2.70 到 5.17，14B 从 5.17 到 10.79）；**不用 1.5 万条专家示范，就能追平"专家 SFT + GRPO"在内部评测上的效果**。
**原文里有意思的发现**
- **GRPO 本身几乎不改变模型对终端输出的预测能力**（环境 token 交叉熵基本不变），尽管成功率在上升。ECHO 则大幅降低在**更强模型（32B）生成的离策略轨迹**上的环境 token 交叉熵（0.29 降到 0.07），说明学到了可迁移的终端动力学。
- 成功率不到 15% 时，大部分 rollout 在 GRPO 中几乎没有梯度，但**失败轨迹里依然有丰富的"环境如何响应"的信息**。
- 格式警告 token 约 60 步就被记住（交叉熵从 5.6 降到 0.05 以下）；真实终端输出的交叉熵停在 0.05 到 0.10，这是不可约熵。所以只对真实输出算损失。
- λ 太大（≥0.1）会塌缩到"输出容易预测但没有用"的退化 rollout，即**为了让环境好预测而去做无聊的动作**。
- **只用环境预测损失、不用任何奖励**继续训练，也能在未见任务上提升（PyTerm +10pp）。前提是过滤掉格式错误的轨迹，否则模型学到的是"失败模式的世界模型"。
- 推理时也更省：8B 的超时率从 19.8% 降到 9%，token 数减少 30%。
**我的看法**
- 与第 9 篇（RAGEN 中的模板坍缩、互信息）、第 26 篇（agent 输出高度可预测）形成对照：**agent RL 中最被浪费的信号是环境的反馈本身**。
- 对 MLLM 的直接类比：在 thinking-with-images（第 48 篇）中，裁剪后返回的图像 token 是环境观测，可以用类似方式让模型"预测裁剪后会看到什么"（例如预测视觉特征）。这可能有助于缓解第 43 篇的"不看图"问题。值得查新。
- "λ 太大导致刻意制造可预测环境"是好奇心或预测奖励的经典陷阱（noisy-TV 的反面），值得留意。

## 65. Signal and Noise: A Framework for Reducing Uncertainty in Language Model Evaluation（NeurIPS'25 D&B Spotlight；AI2 / UW）2508.13144
**一句话**：
- 定义 benchmark 的两个量：
  - **信号** = 同算力下一群模型分数的相对最大差。
  - **噪声** = 单个模型最后 n 个 checkpoint 分数的相对标准差。
- **SNR 与"小模型排序能否预测大模型排序"（决策准确率）的相关性 R=0.79**；单看信号或单看噪声都不相关。目标模型的噪声与 scaling law 外推误差相关。
- 数据规模：375 个模型，30 个 benchmark，90 万条评测结果。
**原文里有意思的发现**
- **最后 n 个 checkpoint 间的噪声**与"换随机种子""换数据顺序"带来的噪声高度相关（R² 为 0.82 到 0.95），所以不需要额外训练就能估计噪声。1B 模型在 ARC-C 上，最后 30 个 checkpoint 之间就有 1.7% 的波动。
- **benchmark 越大不一定越好**：只选 SNR 最高的 16 个 MMLU 子任务，决策准确率就比用全部子任务高 2.6%。低 SNR 的子任务恰好多是标注错误率高的子任务（MMLU-Redux 中错误率 ≥5% 的 20 个子任务里，有 10 个落在 SNR 最低的 20 个中）。
- **换成 bits-per-byte（正确答案的 NLL）而不是准确率**，SNR 大幅提升（GSM8K 从 1.2 升到 7.0，MBPP 从 2.0 升到 41.8）。90% 的 benchmark 决策准确率提高，73% 的 scaling law 误差降低。
- 对最后几个 checkpoint 的分数取平均（或训练过程中取 EMA），能稳定提升决策准确率。
- 某些单任务（TriviaQA、Jeopardy）比多任务平均更容易预测。
**我的看法**
- 与第 20 篇（BF16 下推理模型准确率方差可达 9%）结合，是对"效率论文 +1 到 3 点增益"最有力的方法论武器：**任何 training-free 方法的增益都应当先报告该 benchmark 在该设置下的噪声底**。可以直接计算"同一模型、不同种子或不同硬件"下各 benchmark 的噪声，评估文献中声称的增益是否显著。
- "用 BPB 代替准确率"提示：在研究推理效率方法时，**正确答案的 NLL 可能比准确率更灵敏、更稳定**，适合作为快速筛选指标。

## 66. Inference-Time Reward Hacking in Large Language Models（NeurIPS'25；Harvard）2506.19248
**一句话**：
- 证明在 BoN、BoP 这类满足单调似然比（MLR）的推理时对齐方法下，**真实奖励随优化强度要么单调变化，要么只有唯一一个极值点**。也就是说，"先升后降"的 reward hacking 是这类方法的必然形态，相当于赢家诅咒。
- 提出 **Best-of-Poisson（BoP）**：n 从泊松分布中采样，只有一个参数，在 KL-奖励权衡上与最优的指数倾斜分布之间的 KL 差小于 8e-4，相当于推理时近似 RLHF。
- 提出 HedgeTune：用少量真实奖励样本，通过求根找到 hacking 阈值。
**原文里有意思的发现**
- 理论上可能出现四种形态：单调提升、hacking（先升后降）、**"reward grokking"（先降后升）**、立即下降。
- 即使使用在 RewardBench 上排名第 12 的 Skywork-Llama-3.1-8B RM，**在 GPQA 上 BoN 依然出现 hacking**：n 太大时准确率下降。
- 用分位数变换（经验 CDF）把奖励映射为均匀分布，所有分析只依赖一维的奖励分位数，不需要知道 LLM 的分布。
**我的看法**
- 方法论上很干净，可以直接移植到"自一致性 / 置信度选择"中：第 60 篇（NAD）、第 50 篇（迂回度）这类内部信号也是代理奖励，**同样会被 n 增大带来的赢家诅咒影响**。论文的"选到第 4096 个 token 时反而比完整回答好"可能就是这种现象的一个表现。
- 与第 16 篇（弱验证 / 强验证）结合：弱验证器 + 大 n 必然会出现 hacking，最优 n 应当由验证器质量决定。

## 67. What Makes a Reward Model a Good Teacher? An Optimization Perspective（NeurIPS'25 Spotlight；Princeton PLI）2503.15477
**一句话**：
- 证明：**无论 RM 多准确，只要它在当前策略的高概率输出上诱导的奖励方差低，RLHF 目标就是平坦的**，奖励上升的时间与方差成反比（高阶导数也同时消失）。
- 推论一：完全准确的 RM 可能比不准确的 RM 慢得任意多。
- 推论二：同一个 RM 对不同的初始策略效果不同，所以**RM 不能脱离策略单独评估**。
**原文里有意思的发现**
- 实验：用 ArmoRM 作为"真值"，构造一个"排序完全正确、但输出之间分差被压小"的 RM，**训练效果显著不如一些不太准确的 RM**。
- **在前几个 epoch，用代理 RM 训练甚至比直接用真值奖励训练更快**，因为代理 RM 的方差更大。
- **奖励方差与奖励上升速度强相关；准确率单独看不相关**。方差与准确率的组合最能预测真值奖励的提升。
- 离策略准确率高、在策略准确率低的 RM 是糟糕的老师，并且更容易导致 reward hacking。
- 在不同策略（Pythia、Llama-3.2）上，最好的 RM 不同；RewardBench 分数最低的 RM-Gemma-2B 诱导的方差最高，代理奖励涨得最快，但真值奖励并没有因此上升。
- 在 BoN 中，完全准确的 RM 总是最优的。**准确率的重要性取决于对齐方法**。
**我的看法**
- 与 GRPO 中"组内全对或全错就没有梯度"的现象是同一件事的理论版本：**低奖励方差 = 平坦地形**。也解释了为什么 RLVR 需要"难度合适"的题目（方差最大的 p≈0.5）。
- 与第 30 篇（GRPO 的 std 归一化掩盖多项奖励）、第 64 篇（ECHO 为失败轨迹补充稠密信号）一起，可以看作"**RL 的瓶颈往往是信号方差，而不是信号准确率**"。
- 可迁移的检验：PRM 或过程奖励的价值，可能主要来自增加组内方差，而不是更准确。
